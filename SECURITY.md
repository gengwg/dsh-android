# Security policy

## Supported versions

Security fixes are applied to the latest stable release and the `main` branch.

## Reporting a vulnerability

Report vulnerabilities privately through [GitHub Security Advisories](https://github.com/gengwg/dsh-android/security/advisories/new). Include the affected version, device/Android version, reproduction steps, and potential impact. Do not include launch tokens, cookies, private keys, API keys, signing material, or private server addresses in public issues or pull requests.

Sensitive assets include user prompts and session data, DSH server credentials, release signing material, and CI acceptance credentials. Keep those values out of bug reports; the maintainer can request a private reproduction channel if needed.

## Scope

Reports may cover the Android application, its release pipeline, and maintainer-operated acceptance infrastructure. Also report upstream vulnerabilities to the affected DSH, Expo, React Native, or other dependency owners when appropriate.
